# Архитектура

```
iPhone «Поделиться» ──► Supabase Edge Function add-link ──► таблица sources (status=pending)
                                                              │
Веб-приложение (iPhone/ПК) ◄── читает/пишет ──► SUPABASE (Postgres + Auth)  ◄── единственное «сердце»
                                                              ▲
Обработчик на ПК (запускается вручную) ── забирает pending ──┘
   субтитры YouTube / yt-dlp + faster-whisper → claude -p → карточки (status=draft)
```

**Главное правило:** обработчики общаются только с базой. Новая функция = новый обработчик + пара таблиц, ядро не трогаем.

## Данные (черновик, уточняется на этапе 1)
| Таблица | Что хранит |
|---|---|
| `areas` | сферы: название, цвет, порядок |
| `sources` | url, платформа (youtube / youtube_shorts / instagram / other), заголовок, длительность, транскрипт, статус (pending / processing / done / error), ошибка, даты |
| `cards` | тип, сфера, заголовок, `content` jsonb, статус (draft / approved / rejected), статус действия («хочу попробовать», «сделал»), `source_id`, тайм-код, модель, даты |
| `relations` | связи между сущностями (на будущее; в макете «Связано») |
| `events` | планы и календарь (после MVP; назначение: Напоминания / Google / только в приложении) |

Схемы `content`:
- `recipe`: ингредиенты (продукт, количество), шаги, время;
- `exercise`: техника по шагам, частые ошибки, подходы/повторы;
- `rule`: утверждение + пометка «мнение автора / ссылка на исследование» (в макете — «мнение автора, не проверено»);
- `idea` / `tip`: суть и контекст.

Одно видео может дать несколько карточек. Сферы: Питание, Спорт, Здоровье, Бизнес, ИИ и обучение, Идеи; список настраиваемый.

## Что требует макет от данных
- Входящие: фильтры «все / на проверку / в очереди»; статусы «Ждёт ПК», «Обрабатывается» (с прогрессом и текстом шага), «Готово — проверь», «Ошибка». Значит, у `sources` нужны поля прогресса и текста шага.
- Проверка: у каждой найденной карточки галочка, тайм-код, флаг «не проверено».
- Сегодня: счётчики по сферам, «Давно лежит» (карточка сохранена давно и не запланирована).
- Поиск «по смыслу» и режим «база + интернет» — после MVP (pgvector).

## Утренний помощник (экран «Сегодня», после MVP)
Утром приложение спрашивает: что в холодильнике и сколько времени до выхода, и предлагает завтрак и зарядку из базы. Первая версия без нейросети: фильтры по типизированным карточкам. Для этого с самого начала закладываем:
- `recipe.content`: `time_min`, `meal` (breakfast/lunch/dinner/snack), ингредиенты в нормализованном виде (`product` + `amount` + `unit`);
- `exercise.content`: `equipment` (турник, гиря…), `duration_min`, `muscle_group`;
- таблица `pantry` (продукты, которые обычно есть дома) и профиль пользователя с целью («набор массы»).
ИИ-подбор («почему именно это», меню на неделю) добавляется позже; `claude -p` работает только на ПК, поэтому утром с телефона на него рассчитывать нельзя.

## Обработчик
`summarize()` — единый интерфейс; по умолчанию `claude -p --output-format json` со строгой JSON-схемой, позже Ollama или OpenRouter. Один источник за раз, лог в консоль, ошибки пишутся в `sources.error`.

## Риски
- Supabase и хостинг из РФ без VPN — проверить на этапе 1–2.
- Бесплатный проект Supabase засыпает через неделю без активности.
- Instagram хрупок: нужна понятная обработка ошибок; при включённом VPN возможны блокировки IP дата-центра.
- iOS: PWA не попадает в меню «Поделиться», поэтому вход — через команду iOS (Shortcuts).
